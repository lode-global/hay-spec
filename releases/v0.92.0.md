# Hay Description Specification v0.92.0

**Draft release notes — unreleased. Prepared October 24, 2026.**

Recommended version: **0.92.0**, a minor increment from 0.91.1 because this adds
reporting capabilities rather than only correcting release metadata. The
specification remains a working draft. No tag or GitHub release is created by
this preparation PR. The latest published release remains v0.91.1.

## Changes since v0.91.1

- **Packaging:** consistent `id` keys alongside existing `name` aliases, clarified
  units and precision, and explicit `bale_dimension_axis` for round bales. Preserve
  ambiguous legacy height/length values; do not map them without source evidence.
- **Laboratory provenance:** optional sample ID, report reference, preparation
  completion date, processing notes, and result qualifier.
- **Handling history:** optional definitions within existing `handling_events`,
  including stage labels and source-reported visible degradation. Partial histories
  remain permitted, and existing final-storage summaries remain independent.
- **Nutrient reporting:** optional laboratory moisture percentage, distinct from
  baler readings; one retained `dry_matter` definition with its existing record key.
- **Field conventions and checks:** documented interpretation of identities,
  omissions, and advisory versus explicit constraints, plus structural validation
  and an explicit baseline of known legacy issues.
- **Reference documentation:** reproducible Markdown pages, an exact YAML copy,
  JSON transcription, freshness checks, and a strict local site build.

## Compatibility and known limitations

- No mandatory record migration. Existing protein identifiers containing `%`,
  enum spellings, numeric types, and stored values are retained. Consumers that
  reject unknown properties must allow the new optional fields before using them.
- Nine known source warnings remain: dotted component identifiers, two protein
  identifiers containing `%`, and five pipe-delimited enum lists. Do not silently
  rename or split historical values. See the [backlog](../notes/backlog.md).
- Typical nutrient ranges remain advisory. The new moisture bounds are 0-100
  percentage arithmetic, not an acceptance threshold. Derivations require the
  same sample/basis, retain reported values, and respect destination constraints.
- The JSON is a transcription, not JSON Schema. Structural checks and YAML lint
  do not validate hay records or certify analytical/scientific content.
- Historical version-history prose is retained for provenance; it includes earlier
  refactor claims that do not constitute a verified inventory of implemented fields.
- No documentation deployment is included. License remains CC BY 4.0; contact
  remains standards@lode.global.
